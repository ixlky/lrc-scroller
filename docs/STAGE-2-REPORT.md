## 四、发现并修掉的问题

### 1. 真 bug：无音频无歌词时仍能进入播放态（由用例 5 抓出）
`StageView` 里的 watch 只会在**有**歌词时设置模拟时长，从不归零。于是清空歌词后 `duration` 残留 61 秒，点播放进入"不出声、不报错、时间却前进"的空转态。
**修复**：歌词清空且无音频时显式 `setSimDuration(0)` 并复位播放状态；同时让 `setSimDuration` 在被传 0 时**真的清空**（原先早退，等于无法清零）。

### 2. 我自己写的代码里两个严重问题（写完即自查发现）
- **`sim` / `simRef.value` 混用**：`core/clock.js` 全是纯函数（返回新对象）。我第一版里既保留了 `const sim`，又用 `simRef.value` 写回，导致读到的是过期时钟。**重写为唯一可变容器 `simState`**。
- **引擎可能被实例化多次**：这个 composable 会被 TopBar / PlayerBar / StageView 多处调用，若各自新建 `<audio>` 和 rAF 循环，就会出现"两个音频同时放""暂停只暂停了一个""帧计数翻倍"。**改为模块级单例**。
  > 这与阶段 1 的 `useLrcImport` 是同一类坑（composable 的局部状态 ≠ 全局状态）。区别是那里只要把数据挪进 store，这里还必须保证全局只有一个 `<audio>` 和一条 rAF。

### 3. 我的测试有 3 处写错（均已修正，保留说明）
- **窄视口导致假通过**：用例 6 结束调用了 `clearDeviceMetricsOverride`，后续 N2 测试退回默认 500px 宽。而窄屏下跳行胶囊与音量滑杆是 `display:none`，尺寸为 0 → **"不重叠"是假象**。已改为显式恢复宽视口，并要求元素**必须可见**才算通过。
- **帧计数基线不稳**：直接比较两次读数，跨了暂停/播放边界。已改为分别采集"暂停 500ms"与"播放 500ms"两个等长窗口的帧增量。
- **阶段 0 的两条断言已过时**（不是回归）：它们断言"点导入音频会弹阶段 2 占位提示"，而该功能现在真的能用了；以及"无音频点播放给提示"，而现在有歌词时会正确地走模拟时钟（这正是 N1）。已按新规格更新断言。

### 4. 窄屏策略的取舍（N2）
≤640px 时抽屉全屏覆盖，避让量设为 0。若强行挤压，主内容会被压到几乎不可见。宽屏才做避让 —— 这是有意为之，已在 CSS 变量里注明。
