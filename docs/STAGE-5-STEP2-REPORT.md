# 阶段 5 · 第 2 步交付：N3 纯文本铺开

## 本步改了什么（一句话）

无时间标签的文本行改为渲染在舞台底部的独立静态容器（不进滚动轨道、不带 `data-line-index`、不参与高亮与滚动），并在它们存在时不再显示"还没有歌词"空状态。

---

## 渲染结构（你已确认的三项：分开两容器 / 只要有就显示 / 轨道正下方）

| 决策 | 实现 |
|---|---|
| 分开两个容器 | ✅ 无时间行是 `.stage__untimed`，与 `.stage__track` 平行、在其后 |
| 只要有就显示 | ✅ `showEmpty = !hasLyrics && !showUntimed` |
| 轨道正下方（同屏） | ✅ `position: absolute; bottom: 0`；无轨道时改为撑满全屏并垂直居中 |

**为什么必须分开**（这是关键约束）：`useAutoScroll.measure()` 用 `querySelectorAll('[data-line-index]')` 收集行几何、**按 `dataset.lineIndex` 的值写入数组下标**。无时间行若进轨道，要么不进数组留下空洞、要么给特殊索引污染 `rowMetrics` 长度 —— 两者都会波及 `getBounds` / `findRowAtViewportCenter`。分开容器后，**阶段 3 的滚动逻辑一行都没改**。

# 附：第 5 步 N4 撤销栈状态机设计（按你要求提前给，确认后才写代码）

## A. 两种"撤销"必须区分 —— 这是设计的核心

| | 第 4 步 · `Backspace` | 第 5 步 · `Ctrl+Z` / 撤销按钮 |
|---|---|---|
| 作用对象 | **当前聚焦行的微调值** | **上一行已记录的时间** |
| 触发场景 | 用户刚用 `←→` 微调，想改回来 | 用户刚打完一行，想整行撤掉 |
| 是否动播放头 | **不动** | **回滚到该行起始时间前 1 秒** |
| 是否离开打轴模式 | 不离开 | 不离开 |
| 栈行为 | **不 push**（微调不进栈） | **push 快照 → pop** |

**为什么必须分开**：两者语义正交。若共用一个栈，`Backspace` 会把刚打的行也撤掉 —— 用户只想改 10ms 却丢了整行。

**键位建议**：`Ctrl+Z` = 整行撤销 + 回滚（你说的 N4）；`Backspace` = 只撤微调。两者不冲突。

## B. 状态机

```
                      ┌──────────────────────────────────────┐
                      │        undoStack: Snapshot[]          │
                      │  上限 100，超出丢弃最旧              │
                      └──────────────────────────────────────┘

  每次「记录一行时间」成功
        │
        ├─ push({ lineId, prevT, newT, prevLocked, rowIndex })
        │
        └─ 写入 line.t = newT, line.locked = false

  每次「Ctrl+Z」
        │
        ├─ stack 为空 → 无反应（不报错、不弹提示）
        │
        ├─ pop 出一个快照
        │
        ├─ line.t = prevT（恢复或清空）
        │   line.locked = prevLocked
        │
        ├─ 播放头回滚到 max(0, prevT - 1000)   ← 回滚位置
        │
        ├─ 播放状态保持原样
        │   · 原本 playing → 保持 playing（从新位置继续播）
        │   · 原本 paused  → 保持 paused（只跳过去，不自动播）
        │
        └─ 焦点回到该行
```

## C. 几个关键时机的明确回答

**① 什么时候 push？**
只在「记录一行时间」时 push —— 包括空格打轴、拖拽打轴、以及**改写已有时间的再次打轴**（覆盖也算一次变更）。
**`←→` 微调不 push**（那是 Backspace 的职责）。
`BeatPanel` 吸附导致的时间变化**也不 push**（它是本次记录动作的内部细节，已包含在同一次 push 里）。

**② 什么时候 pop？**
只有 `Ctrl+Z`。每次 pop 一个。栈空时无反应。

**③ 退出打轴模式后如何保留？**（你已确认：保留）
撤销栈**挂在打轴会话对象上，不随模式开关销毁**。退出模式只置 `enabled=false`，栈原样留着；重新进入时栈还在。
→ 副作用：关闭再打开仍能撤销到进入之前打过的行。**这正是你想要的**（临时去看看别的，回来还能撤销）。

**④ 栈满 100 层后？**
丢弃**最旧**的一个（`shift()`），保留最近的 100 层。多级撤销仍然可用，只是不能回到太久远。

**⑤ 撤销第一行时？**
`prevT` 为空 → 回滚位置 = `max(0, 0 - 1000)` = **0 秒**。不出现负数。

**⑥ 回滚落点在某句中间？**
不处理、不对齐行首。`prevT - 1000` 就是那个位置。

**⑦ 微调过的行被撤销？**
快照里存了 `prevLocked`，恢复时一并还原。若该行是**先微调、后被打轴覆盖**，撤销后应回到"无时间"状态（`prevT = null`）。
