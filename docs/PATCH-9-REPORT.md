## 一、rowCount 残留（第 3 步前置修复）

## 三、发现并修复的一个真 bug（在本轮范围内）

**症状**：设置面板里明明显示黑色，拖色相环却只出白色。

**根因**：`ColorPicker` 用 `let selfUpdate = false` 标记"这次更新是我自己发的"，靠下一次 `watch` 清掉。但 **Vue 的 watch 只在值真的变化时才触发**：

```
1. 颜色是 #ffffff，拖色相环 → 所见即所得下颜色**不变**
   → emit('#ffffff')，而 modelValue 本来就是 '#ffffff'
   → watch 不触发 → selfUpdate 永远是 true
2. 之后外部把颜色改成 #000000 → watch 触发
   → 第一个分支把 selfUpdate 清掉并 return → **localHsl 没被更新**
3. 用户再拖色相环，用的是旧的白色 HSL → 出来还是白色
```

这个 bug 在补丁 6 时代**不会出现**（因为灰色拖动会自动提饱和，值总在变，watch 总会触发）。**是"所见即所得"把它暴露出来的** —— 值不变本是正确行为，却让这个标记逻辑永久卡死。

**修法**：不再依赖"下一次 watch 会来清"，改为**记住自己发出的值**，只有当 watch 收到的值**恰好等于自己发出的那个值**时才跳过：

```js
let selfEmitted = null
watch(() => props.modelValue, (v) => {
  if (selfEmitted !== null && v === selfEmitted) { selfEmitted = null; return }
  selfEmitted = null
  const c = hexToRgb(v)
  if (c) localHsl.value = rgbToHsl(c.r, c.g, c.b)
})
function commitHex(nextHex, hsl) {
  if (hsl) localHsl.value = hsl
  selfEmitted = nextHex
  emit('update:modelValue', nextHex)
}
```

**定位方法**（值得记）：我一度以为是 `settings.set()` 没生效，写了独立脚本逐步快照 store / HEX 输入框 / RGB 滑杆 / 环心背景 —— 单独测时全部正常。**只有在完整套件里才复现**。于是改为主动构造最小复现路径（"设纯白 → 拖环 → 设纯黑 → 再拖环"），一次跑通并打印出每一步，才看到第 2 步 emit 了相同值这个关键事实。

## 四、按钮文案

「导入 LRC」→「导入 txt / lrc」。**只改文案，功能未变**（`accept` 仍同时含 `.lrc` 与 `.txt`，已加断言守住）。

**顺带修了一个它引发的溢出**：文案多了 5 个字符，在 375px 视口下把顶栏撑到 377px，产生 2px 横向溢出（`e2e-stage0` 抓到的）。修法用**容器查询**而非固定断点 —— 顶栏实际宽度取决于按钮文案长度而非视口宽度，固定断点在文案再变一次时就会失效：

```css
.topbar { container-type: inline-size; container-name: topbar; }
@container topbar (max-width: 430px) {
  .topbar__actions .btn { padding: 7px 9px; font-size: 12px; }
}
```

> 踩坑记录：`container-type` 必须写在**被查询元素的祖先**上。最初我写在 `@container` 规则内部，元素会先按普通元素布局、再决定自己是否成为容器，规则永远匹配不上（自指，浏览器直接忽略）。已修正并写进注释。
