## 第 1 步 · 节拍网格核心算法（纯函数，先不碰 UI）

**做什么**
- 新建 `core/beat.js`：`beatTimes(bpm, firstBeatMs, barsBeats)` → 节拍时间数组
- 校验：`bpm` 必须 > 0 且有限；非法值**拒绝并保留原值**（不静默改写）
- 吸附：`nearestBeat(t, grid, toleranceMs)` → 命中返回 `{t, index}`，未命中返回 `null`

**验收清单**
1. BPM=120、第一拍=0ms → 网格点出现在 `0, 500, 1000, 1500…`（误差 ≤1ms）
2. 第一拍偏移 250ms → 整个网格平移 0.25s（`250, 750, 1250…`）
3. BPM=60 → 间隔 1000ms；BPM=240 → 间隔 250ms
4. BPM 非法（0 / 负数 / 文本 / `NaN` / `Infinity`）→ 校验函数返回错误，**原值不被改写**
5. BPM=120 但采样点小数截断（如 33.333ms/拍）→ 累积误差 ≤1ms（必须用"逐拍累加"而非 `i * interval`，否则第 100 拍会漂移几毫秒）
6. 吸附：打 1.23s、节拍在 1.25s、容差 50ms → 命中 1.25s 并返回 index=2
7. 吸附：打 1.23s、容差 10ms → **不命中**（返回 null，不擅自改用户的数）
8. 容差为 0 → 只在浮点误差内命中
9. `barsBeats=0` / 负数 → 返回空数组，不抛异常

**产出**：`core/beat.js` + `test-core.mjs` 新增分组（纯函数，可 Node 直测）

## 第 2 步 · N3 纯文本铺开（无时间标签的行可见）

**做什么**
- `droppedLines` 从"只在信息面板里列出来"变成"**在舞台上按换行逐行显示**"
- 这些行**不高亮、不滚动**（没有时间轴，无法参与播放定位）
- 导入纯 `.txt` → 舞台上直接出现逐行歌词 → 用户可进入打轴补时间

**验收清单**
1. 导入无任何时间标签的 `.txt` → 舞台逐行显示，`droppedLines` 数量与文本行数一致
2. 这些行**不带 `is-active`**、不放大、不变色
3. 播放时它们**不参与滚动定位**（`activeIndex` 不指向它们）
4. 已有 LRC（含时间标签）导入 → 行为与现在**完全一致**（不回归）
5. 混合文件（一部分有时间标签、一部分没有）→ 两类都显示，有时间的照常滚动，无时间的静止
6. 纯文本 5000 行 → 帧率无明显下降（沿用阶段 3 结论：不虚拟滚动，但要确认 5000 行静态渲染不卡）
7. 空行、纯空白行 → 不产生空的可视行

**产出**：`StageView` 渲染分支 + `LyricsInfoPanel` 相应调整

## 第 3 步 · 打轴模式与空格记录（核心交互）

**做什么**
- 打轴模式开关（设置里，或面板上的按钮）
- 开启后**空格从"播放/暂停"改为"记录当前时间"**，`useKeyboard` 按模式分派
- 记录后：焦点自动跳下一行，列表滚动跟随
- 播放状态下也能打轴（用 `currentTime`；暂停状态下用当前值）

**验收清单**
1. 开启打轴模式 → 空格不再切换播放/暂停
2. 播放中按空格 → 当前行记录 `currentTime`，焦点跳到下一行
3. 连按空格 5 次 → 5 行依次获得**递增**时间，无重复无丢失
4. 记录的行**立即出现在舞台上**（`is-active` 跟随该行）
5. 关闭打轴模式 → 空格恢复为播放/暂停（不回归）
6. **未导入音频时**（模拟时钟）也能打轴 —— 时间取自模拟时钟
7. 聚焦在输入框时按空格 → 是"输入空格"，**不触发打轴**
8. 已打过时间的行再次打轴 → **覆盖**（而不是新增一行）
9. 最后一行为空行（间奏）→ 记录时间但不高亮文字
10. 全部行打完 → 有明确完成提示，焦点停在末尾不再前进

**产出**：`useTapping.js`（打轴状态机）+ `SyncPanel.vue` 骨架

## 第 4 步 · ←→ 微调与 Backspace 回退

**做什么**
- `←` / `→`：当前行时间 ∓10ms（按住 `Shift` 为 100ms）
- `Backspace`：撤销当前行的时间（还不回滚播放头 —— 那是 N4）

**验收清单**
1. `←` → 当前行时间 −10ms
2. `→` → +10ms
3. `Shift+←` / `Shift+→` → ∓100ms
4. 边界：时间被减到 < 0 → **夹到 0**，不产生负数
5. 边界：时间被加到 > 下一行时间 → **夹到下一行 −1ms**，不与下一行撞车
6. 边界：最后一行无上限限制（可超过原时长）
7. 未选中任何行时按 `←`/`→`/`Backspace` → 无反应，不报错
8. 聚焦在输入框时 → 是"输入字符"，不触发微调
9. 连续微调 50 次 → 累积无浮点漂移（1230ms 加 10 次应为 1330ms，不是 1329.999）

**产出**：`useTapping.js` 扩展

## 第 5 步 · N4 撤销并回滚（合并版，多级栈）

**做什么**（严格按你已确认的定义）
- **单一动作**：撤销上一行打轴记录 + 播放头回滚到**被撤销那一行的起始时间前 1 秒** + 焦点回到该行
- 播放状态保持原样：原本在播 → 从新位置继续播；原本暂停 → 只跳过去，不自动播
- 多级撤销栈
- 撤销第一行 → 回滚到 0 秒
- 回滚位置落在某句中间**不需要**对齐到行首

**验收清单**
1. 打完 3 行 → 撤销一次 → 撤销的是**最后一行**，前 2 行保留
2. 撤销后播放头回到**第 3 行起始时间 − 1 秒**（不是固定 5 秒）
3. 原本在播放 → 撤销后**仍在播放**，且从新位置继续
4. 原本暂停 → 撤销后**仍暂停**，只跳过去
5. 连续撤销 3 次 → 逐级回退，第 4 次无反应
6. 撤销栈非空时退出打轴模式再回来 → 栈**保留**（或明确清空，二选一，需你定）
7. 撤销第一行 → 播放头回 **0 秒**，不出现负数
8. 撤销后**焦点回到被撤销那一行**（不是回到第一行）
9. 回滚落点在某句中间 → **不要求**对齐行首
10. 撤销栈深度上限 → 超出后丢弃最旧的（需你定上限，建议 100）
11. 一行都没打就撤销 → 无反应
12. 微调（←→）过的行被撤销 → 该行时间**完全消失**（不是回到微调前的值）

**产出**：`useTapping.js` 撤销栈

## 第 6 步 · 节拍网格 UI 与吸附

**做什么**
- 面板输入 BPM + 第一拍偏移 → 实时显示网格
- 网格叠加在歌词上（细线/刻度）
- 「吸附最近节拍」开关：打轴时自动吸到最近网格点，并标 `beat` 序号
- 手动微调过的行标 `locked`，**不被吸附覆盖**

**验收清单**
1. 输入 BPM=120、第一拍=0ms → 网格出现在 `0, 0.5, 1.0…`
2. 第一拍偏移 250ms → 网格整体平移
3. BPM 非法（0/文本/负数）→ **输入框拒绝并保留原值**，红色提示
4. 打开吸附 → 打 1.23s、节拍在 1.25s → 记录为 1.25s 并标 `beat` 序号
5. 打开吸附 → 打 1.23s、超出容差 → **不吸附**，保留 1.23s
6. 手动 `←→` 微调过的行标 `locked` → 再开吸附**不被覆盖**
7. 关闭吸附 → 全部按原始时间打轴
8. BPM 在播放中途修改 → 网格实时重算，**已有行的 `beat` 序号重算**
9. 网格线不遮挡歌词文字（半透明细线）
10. 100 行 × 120BPM → 网格渲染不卡（复用阶段 3 的 `will-change` 策略，不给每条线加动画）

**产出**：`BeatPanel.vue`
