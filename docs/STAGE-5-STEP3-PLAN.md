## 一、三个问题的回答

### Q1：`useKeyboard` 是否集中处理空格？有组件在抢吗？

**`useKeyboard` 集中处理，全项目无任何组件抢空格。** 实测全项目 5 处 `@keydown`：

| 位置 | 处理哪些键 | 碰空格吗 |
|---|---|---|
| `PlayerBar` `onSeekKeydown` | ←/→/Home/End | ✗ |
| `PlayerBar` `onVolumeKeydown` | ←/→/Home/End/↑/↓ | ✗ |
| `StageView` `onScrollKeydown` | ↑/↓/PageUp/PageDown/Home/End | ✗ |
| `ColorPicker` `onRingKeydown` | 方向键（调色轮） | ✗ |
| `ColorPicker` `onBarKeydown` | ↑/↓（调明度） | ✗ |

**结论：走「改 `useKeyboard` 加模式判断」，不挂新监听器。** 理由：

1. 空间键在**一个地方**被决定（`useKeyboard` 的 `case ' '`）。挂新监听器会出现两个 handler 都响应，需要 `preventDefault` + `stopPropagation` 打架，而 keydown 是**冒泡**到 window 的 —— 谁先执行取决于注册顺序，脆。
2. `isTypingTarget` 这类输入保护只写一遍。挂新监听器的话，"在输入框里按空格不能打轴"这个规则要写两遍，迟早漏一处。
3. 阶段 2 攒下的 `isTypingTarget` / `canPlay` / `e.ctrlKey` 判断可以原地复用。
4. 阶段 4 的 F/Esc 已经是这个模式（`useKeyboard` 里 `case 'f'` 调 `full.toggle`），**空格与它是同类需求**，分开处理反而不一致。

**唯一要小心的是 `<button>` 的原生空格激活**：播放/暂停是 `<button>`，焦点在它上面时按空格会同时触发「按钮 click」和「我的 keydown 处理」。现有代码靠 `e.preventDefault()` 挡住 —— 打轴模式开启时必须**继续** `preventDefault`，否则会误触发播放。我会在方案里显式写这条。

### Q2：打轴模式开关放哪？

**同意你的倾向：放播放控制栏，和播放/暂停同排。** 具体：

- 位置：`PlayerBar` 里播放键旁边，图标按钮（`⏱` 或 `轴`），`aria-pressed` 表达开关态
- 理由：打轴是"播放控制"的一种模式，与播放/暂停同属一个心智分组；放一起鼠标不用来回移动
- 开启时视觉上要**明确**：按钮点亮 + 播放条上加一条"打轴中"标记（避免用户忘了自己开着模式然后空格没反应）
- 快捷键：`T`（Tap）切换 —— 与 F（全屏）、M（静音）风格一致

**备选方案**：放设置面板。缺点是设置面板是"调参数"的地方，打轴是"高频操作开关"，语义不搭，且每次开关要跑到抽屉里。**不推荐。**

### Q3：空格在打轴模式下：只记录，还是记录后自动跳下一行？

**建议：记录后自动跳下一行。** 这正是阶段 1 验收清单里写的行为（"点空格 → 当前行记录时间，焦点自动跳到下一行，列表滚动跟随"），也是打轴这个交互的全部效率来源 —— 用户的手不离开键盘，一行接一行打下去。

**具体语义**

| 情况 | 行为 |
|---|---|
| 有聚焦行 | 记录 `currentTime` → 焦点移到下一行 → 列表滚动跟随 |
| 该行已有时间（覆盖） | 覆盖，不是新增；仍跳下一行 |
| 聚焦在最后一行 | 记录后停在末尾，**焦点不越界**；给一个"打完了"提示 |
| 目标行是间奏空行 | 照常记录时间（间奏也需要起点），只是不显示文字 |
| 没有聚焦行 | 从**第一行**开始打（而不是无反应），避免用户不知道从哪开始 |

**副作用要处理**：自动跳行会触发 `activeIndex` 变化 → 可能引起自动滚动 → 与阶段 3 的"用户回看保护"打架。处理方式：跳行时把那次滚动标记为**程序触发**（复用 `useAutoScroll` 已有的 `resumeFollow` 思路），不能算作用户在看，否则会出现"打轴时画面自己跑"。

## 二、空格的优先级（三处）

按你问的顺序，从高到低：

```
1. 正在输入（input / textarea / [contenteditable]）
   → 空格 = 打一个空格字符，**其余什么都不做**
   （现有 isTypingTarget 已覆盖，改动零成本）

2. 焦点在 <button> 上（如播放/暂停）
   → 现有的 e.preventDefault() 会挡掉按钮的原生激活，
     只走我们的逻辑。这个行为**保持不变**，
     打轴模式开启时同样要 preventDefault（见 Q1 的提醒）

3. 打轴模式开启
   → 空格 = 给聚焦行打一个时间点（+ 自动跳下一行）
     不再切换播放/暂停

4. 其余情况
   → 空格 = 播放/暂停（现有行为，完全不变）
```

**`canPlay` 的处理**：非打轴模式下空格没音频会弹「请先导入音频」提示。**打轴模式下不弹** —— 没有音频时模拟时钟照样能走时间轴（阶段 1 就有这个能力），打轴本来就不需要音频。弹提示反而会打断连续打轴的节奏。

## 四、验收清单（第 3 步）

1. 播放条出现「打轴」开关按钮；点击进入，**按钮点亮 + 播放条显示"打轴中"**
2. 打轴模式开启 → 按空格**不再切换播放/暂停**（播放状态不变）
3. 播放中按空格 → 聚焦行记录 `currentTime`，**焦点自动跳到下一行**
4. 连按空格 5 次 → 5 行依次获得**递增**时间，无重复无丢失
5. 焦点跟随滚动（下一行在视口内可见）
6. **未导入音频**（模拟时钟）也能打轴，且**不弹"请先导入音频"**
7. 对已打过时间的行再按空格 → **覆盖**（不新增一行）
8. 聚焦在最后一行按空格 → 记录后**焦点不越界**，给"打完了"提示
9. 打轴模式下点播放/暂停按钮 → **仍能正常切换**（按钮不被误挡）
10. 关闭打轴模式 → 空格恢复为播放/暂停（不回归）
11. 在 HEX 输入框里按空格 → 是"输入空格"，**不触发打轴**
12. 按 `T` 键可切换打轴模式
13. 打轴过程中**画面不自己乱跑**（程序滚动与用户回看保护不打架）
14. 控制台 0 error
